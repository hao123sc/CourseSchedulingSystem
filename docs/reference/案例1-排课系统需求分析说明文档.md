# 学校智能排课系统 — 需求分析说明文档

> 版本：v1.0
> 日期：2026-06-17
> 状态：需求分析阶段

---

## 一、项目背景

每学期开学，学校需为各年级、各班级安排课程表。传统手工排课耗时长、冲突多、调整频繁，需要一个系统化的排课工具来管理基础数据、设定排课规则、自动生成课表并支持人工微调。

---

## 二、核心业务流程

```
基础数据维护 → 排课规则设定 → 自动排课 → 课表查看与手动调整 → 课表发布
```

1. **基础数据维护**：录入年级、班级、教师、学生、学科、教室等
2. **排课规则设定**：配置每个班每周各学科课时数、教师任教关系、教室可用时段等
3. **自动排课**：根据规则和约束，算法自动生成课表
4. **课表查看与手动调整**：检查冲突、手动换课/调课
5. **课表发布**：锁定并发布最终课表，供师生查询

---

## 三、实体与数据模型分析

### 3.1 基础实体

| 实体 | 核心字段 | 说明 |
|------|----------|------|
| **学校** | 学校ID、名称、学期 | 顶层组织，支持多校区 |
| **学期** | 学期ID、名称、起止日期、当前状态 | 排课以学期为单位，如"2026春季学期" |
| **年级** | 年级ID、名称、排序 | 如：一年级~六年级 / 初一~初三 / 高一~高三 |
| **班级** | 班级ID、名称、年级ID、班主任ID、人数 | 每个年级下多个班级 |
| **学科** | 学科ID、名称、简称、类别 | 如：语文、数学、英语、体育、美术... |
| **教师** | 教师ID、姓名、工号、学科ID、手机号 | 一位教师可任教多学科 |
| **学生** | 学生ID、姓名、学号、班级ID | 按班级归属 |
| **教室** | 教室ID、名称、类型、容量 | 普通教室/实验室/操场/音乐室等 |

### 3.2 关联实体（排课关键）

| 实体 | 核心字段 | 说明 |
|------|----------|------|
| **课时计划** | ID、班级ID、学科ID、周课时数 | 每个班每周每门课的课时数，如"三(1)班 数学 5节/周" |
| **教师任课** | ID、教师ID、班级ID、学科ID、周课时数 | 教师在某班教某课，如"张老师 教 三(1)班 语文 6节/周" |
| **时间段** | ID、节次、开始时间、结束时间 | 每天8节课：第1节~第8节 |
| **星期** | ID、星期几(1~5/1~7) | 周一~周五（部分学校含周六） |
| **课时槽** | ID、星期ID+节次ID | 全局时间格，如"周一第3节"，每周共 5×8=40 个槽位 |

### 3.3 课表实体（排课结果）

| 实体 | 核心字段 | 说明 |
|------|----------|------|
| **课表项** | ID、学期ID、班级ID、学科ID、教师ID、教室ID、课时槽ID | 一条记录 = 某班某节课的完整安排 |
| **调课记录** | ID、原课表项ID、新教师ID/新教室ID/新课时槽ID、原因、操作人 | 支持调课留痕 |

## 四、排课规则与约束

### 4.1 硬约束（必须满足，否则排课无效）

| 编号 | 约束 | 说明 |
|------|------|------|
| H1 | **教师时间不冲突** | 同一教师在同一课时槽只能上一门课 |
| H2 | **班级时间不冲突** | 同一班级在同一课时槽只能有一门课 |
| H3 | **教室时间不冲突** | 同一教室在同一课时槽只能被一门课占用 |
| H4 | **课时数守恒** | 每个班每周每学科排课节数 = 课时计划中设定的周课时数 |
| H5 | **教师课时数守恒** | 每个教师每周总排课节数 = 其各任课班级课时之和 |

### 4.2 软约束（尽量满足，可违反但有优先级）

| 编号 | 约束 | 说明 | 优先级 |
|------|------|------|--------|
| S1 | **课程分散** | 同一学科同一班的课尽量分散在不同天，避免一天连上多节 | 高 |
| S2 | **主课优先上午** | 语文/数学/英语尽量排在上午 | 高 |
| S3 | **体育课下午优先** | 体育课尽量不排在上午第1~2节 | 中 |
| S4 | **教师日课量均衡** | 同一教师每天排课尽量均匀，避免一天7节另一天0节 | 中 |
| S5 | **连堂课** | 某些课需要连续2节（如实验、美术），尽量排相邻节次 | 中 |
| S6 | **教师偏好时段** | 教师可申报不排课时段（如周三上午有教研活动） | 低 |
| S7 | **合班课/走班** | 选修课多个班同一时段上，需合并教室或分班 | 低 |

## 五、排课算法分析

### 5.1 问题本质

排课本质是一个**约束满足问题（CSP, Constraint Satisfaction Problem）**，已被证明是 NP 完全问题。变量是"每个班的每个课时槽安排哪门课+哪位教师"，域是所有可能的(学科,教师,教室)组合，约束即上述硬/软约束。

### 5.2 推荐算法路线

| 算法 | 思路 | 优点 | 缺点 |
|------|------|------|------|
| **贪心+回溯** | 逐课时槽填入，冲突时回溯 | 实现简单，速度快 | 容易陷入局部最优，大规模时回溯爆炸 |
| **遗传算法（GA）** | 种群进化+交叉变异 | 全局搜索，软约束优化好 | 参数调优难，收敛慢 |
| **模拟退火（SA）** | 随机扰动+概率接受劣解 | 实现中等，跳出局部最优 | 需要精心设计冷却策略 |
| **整数规划（ILP）** | 建模为0-1规划，用求解器 | 精确求解，可证最优 | 规模大时求解慢，需商业求解器 |

### 5.3 推荐方案：两阶段策略

```
阶段一：贪心构造初始解
  → 按优先级填充（主课优先 → 副课 → 特殊课）
  → 只保证硬约束

阶段二：局部搜索优化
  → 随机交换两个课时槽的课
  → 计算软约束惩罚分，接受改进的交换（模拟退火思想）
  → 迭代N次或直到惩罚分不再下降
```

**理由**：
- 阶段一快速产出可用课表，不依赖复杂算法
- 阶段二渐进优化，可控、可中断、结果可解释
- 中等规模学校（50个班以内）秒级出结果

### 5.4 算法评估指标

| 指标 | 计算方式 |
|------|----------|
| 硬约束违反数 | 必须为0，否则排课失败 |
| 软约束惩罚分 | 各软约束违反次数 × 权重 之和 |
| 课程分散度 | 同学科同天连排次数 |
| 教师日负荷方差 | 教师每天课时数的标准差 |

## 六、功能模块划分

| 功能 | 说明 |
|------|------|
| 年级管理 | 增删改查，支持排序 |
| 班级管理 | 增删改查，归属年级，设置班主任和人数 |
| 学科管理 | 增删改查，设置类别（主课/副课/活动） |
| 教师管理 | 增删改查，设置可教学科 |
| 学生管理 | 增删改查，分班 |
| 教室管理 | 增删改查，设置类型和容量 |

### 6.2 排课规则配置

| 功能 | 说明 |
|------|------|
| 课时计划设置 | 每个班每周每学科课时数 |
| 教师任课设置 | 教师在哪些班教哪些课 |
| 连堂课设置 | 标记哪些学科需要连排2节 |
| 教师不可排课时段 | 教师申报的不可用时段 |
| 特殊教室绑定 | 某些课必须用特定教室（如化学→实验室） |

### 6.3 排课引擎

| 功能 | 说明 |
|------|------|
| 一键排课 | 触发算法，自动生成课表 |
| 排课进度 | 显示算法运行状态 |
| 排课结果评估 | 展示硬/软约束满足情况和惩罚分 |

### 6.4 课表查看与调整

| 功能 | 说明 |
|------|------|
| 班级课表 | 按班级查看周一~周五课表 |
| 教师课表 | 按教师查看个人课表 |
| 教室课表 | 按教室查看占用情况 |
| 全校总课表 | 鸟瞰视图 |
| 手动调课 | 拖拽/选择式换课，实时冲突检测 |
| 调课记录 | 调课历史留痕 |

### 6.5 课表发布与查询

| 功能 | 说明 |
|------|------|
| 课表锁定 | 锁定后不可修改 |
| 课表发布 | 师生可查询本人课表 |
| 课表导出 | 导出为 Excel / PDF |

## 七、扩展场景（远期考虑）

| 场景 | 说明 |
|------|------|
| **走班制/选课** | 高中选课走班，学生按选课组合排课，复杂度大幅提升 |
| **多校区** | 不同校区独立排课或统一排课 |
| **临时调课** | 某天某教师请假，需临时换课代课 |
| **跨学期复用** | 上学期课表微调后复用到新学期 |
| **考场编排** | 期末考试考场编排，与排课逻辑类似 |
| **课表冲突预警** | 教师请假/教室维修时自动提示受影响课表 |

## 八、技术方案建议

### 8.1 数据库

- MySQL 存储基础数据和课表结果
- 核心表约 10~12 张（见第三节实体分析）
- 课表项表是高频读写表，建议加索引：(学期ID, 班级ID, 课时槽ID)

### 8.2 后端

- Node.js + Express（与现有项目栈一致）
- 排课算法模块独立封装，可单独替换算法实现
- 提供 RESTful API 供前端调用

### 8.3 前端

- Vue.js + TailwindCSS（与现有项目栈一致）
- 课表展示用周视图网格组件
- 手动调课用拖拽交互

### 8.4 排课算法

- 先实现贪心+回溯的 MVP 版本
- 后续迭代加入模拟退火优化
- 算法参数（软约束权重、迭代次数等）可配置

## 十、关键风险

| 风险 | 影响 | 应对 |
|------|------|------|
| 排课组合爆炸 | 大规模学校（100+班）排课耗时过长 | 分年级独立排课，减少搜索空间 |
| 规则冲突无解 | 教师资源不足导致硬约束无解 | 排课前校验资源充分性，提示缺教师 |
| 手动调课破坏约束 | 换课后引入新冲突 | 调课时实时检测，阻止违规操作 |
| 连堂课/合班课复杂度 | 特殊课排课逻辑与普通课不同 | 单独处理特殊课，优先排入再排普通课 |

## 1. 问题形式化

### 1.1 变量

对每条教学任务 $t \in T$（班级 $c_t$、学科 $s_t$、教师 $p_t$、周课时 $n_t$），拆解为 $n_t$ 个**课时单元**（lesson unit）。连堂的 $k$ 节合并为一个不可分割的**块单元**。

记全部单元集合为 $L$，$|L| \approx$ 240 班 × 35 节 = 8400。

每个单元 $l$ 需赋值：

$$x_l = (\text{slot}, \text{room}) \in D_l$$

$D_l$ 为其值域：合法时间槽 × 合法教室。

### 1.2 硬约束 $H$（违反即无效）

| 编号 | 约束             | 形式化                                                                                                                                   |
| ---- | ---------------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| H1   | 班级唯一         | $\forall c, \text{slot}:                                                                                                                 | \{l : c_l = c, \text{slot}_l = \text{slot}\} | \le 1$ |
| H2   | 教师唯一         | $\forall p, \text{slot}:                                                                                                                 | \{l : p_l = p, \text{slot}_l = \text{slot}\} | \le 1$ |
| H3   | **场地并发容量** | $\forall r, \text{slot}: \sum_{l \in L(r,t)} \text{slotsTaken}(s_l, r) \le \text{concurrentCapacity}(r)$　（普通教室该值=1，退化为独占） |
| H3b  | **人数容量**     | $\forall l:\ \text{studentCount}(c_l) \le \text{capacity}(r_l)$                                                                          |
| H4   | 课时守恒         | 每条任务恰好排满 $n_t$ 节                                                                                                                |
| H5   | 禁排时段         | 规则值为 `FORBIDDEN` 的 (作用域, slot) 不可用                                                                                            |
| H6   | 教室匹配         | 需专用教室的学科只能排入 `subject_classroom` 允许的教室                                                                                  |
| H7   | 预排锁定         | `fixed_lesson` 占位不可侵占                                                                                                              |
| H8   | 硬互斥组         | 组内成员不得同时段（教师互斥组、学科互斥同时段）                                                                                         |
| H9   | 拼合/同时上课    | 组内任务必须同槽                                                                                                                         |
| H10  | 连堂完整         | 块单元的 $k$ 节必须相邻且同日，不跨上下午分段                                                                                            |
| H11  | 走班学生冲突     | 共享 `origin_class` 的虚拟班不得同槽                                                                                                     |

**单双周处理**：`odd` 与 `even` 的两条任务可共享同一 slot（错周上课），冲突检测时按 `week_mode` 做位掩码判断：`all` 占 `0b11`，`odd` 占 `0b01`，`even` 占 `0b10`，冲突 ⟺ 掩码按位与非零。

### 1.3 软约束 $S$ 与目标函数

$$
\text{Cost}(X) = \underbrace{M \sum_{h \in H} v_h(X)}_{M = 10^6} + \sum_{s \in S} w_s \cdot v_s(X)
$$

| 代码 | 软约束           | 计算                                                            | 均衡档权重         |
| ---- | ---------------- | --------------------------------------------------------------- | ------------------ |
| S1   | 同班同科同日超限 | $\sum \max(0, cnt_{c,s,d} - \text{daily\_max})^2$               | 40                 |
| S2   | 学科周内分布不均 | 各学科上课日间隔的标准差                                        | 30                 |
| S3   | 主课未排上午     | 重要性≥4 的学科排在下午的节数                                   | 25                 |
| S4   | 违反 `AVOID`     | 命中 AVOID 的节数                                               | 20                 |
| S5   | 命中 `PREFERRED` | 命中数（**负权，奖励**）                                        | −10                |
| S6   | 教师日课时方差   | $\sum_p \text{Var}_d(\text{cnt}_{p,d})$                         | 25                 |
| S7   | 教师空隙课       | 教师某日首末节之间的空档数                                      | 15                 |
| S8   | 教师跨楼栋连堂   | 相邻两节在不同 building 的次数                                  | 10                 |
| S9   | 连堂未相邻       | 块被打散的次数（H10 兜底为软）                                  | 35                 |
| S10  | 单日难度超载     | 某班某日 $\sum$importance 超阈值的部分                          | 20                 |
| S11  | 与基线课表差异   | 增量重排时，变动的课时数                                        | 50（仅增量时启用） |
| S12  | 教师整日无课奖励 | 教师有完整空闲日的数量（**负权**）                              | −8                 |
| S13  | 班级空白日       | 某班某学科整周某日无课导致的失衡                                | 12                 |
| S14  | **场地过度拥挤** | 场地占用率 >80% 的时段数（留余量应对临时调课）                  | 10                 |
| S15  | **场地闲置不均** | 各体育场地使用率的标准差（避免都挤田径场、篮球场空着）          | 8                  |
| S16  | **班级首节空堂** | 班级当天有正课、但第一节正课为空的天数；早读/晚自习不算正课首节 | 200                |

S16 保持为高权重软约束：构造期优先填充各班每日第一节，质量优化继续精修；在教师、场地或预排限制过紧时仍允许保留少量首节空堂，不把问题升级成硬约束导致无解。预排在第一节的正式课程会计入占用，早读等非正课不会冒充第一节。

**三档风格权重预设**：

| 软约束           | 教师优先 | 均衡 | 学生优先 |
| ---------------- | -------- | ---- | -------- |
| S1 同科同日      | 30       | 40   | 55       |
| S2 周内分布      | 20       | 30   | 45       |
| S3 主课上午      | 15       | 25   | 40       |
| S6 教师方差      | 45       | 25   | 12       |
| S7 教师空隙      | 40       | 15   | 8        |
| S12 教师空闲日   | −25      | −8   | −2       |
| S10 单日难度     | 12       | 20   | 35       |
| S16 班级首节空堂 | 160      | 200  | 240      |

## 3. 阶段 0：预处理与自检

### 3.1 冲突图构建

```ts
// 两个单元冲突 ⟺ 共享班级 / 教师 / 唯一教室 / 走班学生源 / 同属硬互斥组
function buildConflictGraph(units: Unit[]): AdjacencyList {
  const byClass = groupBy(units, (u) => u.classId)
  const byTeacher = groupBy(units, (u) => u.teacherId)
  // ... 组内两两连边，实际用「组 id → 成员列表」隐式表达，避免 O(V²) 显式建边
}
```

**实现要点**：8400 个顶点显式建边会产生千万级边。改用**隐式冲突组**表示，冲突判定 O(1)，无需存边：

```ts
// 班级、教师：容量恒为 1 → 用位图，判定即按位与
classOccupancy: Uint32Array // [classId][slotWord]，含单双周掩码
teacherOccupancy: Uint32Array // [teacherId][slotWord]

// ★ 场地：容量可 >1 → 不能用位图，改用「已占班位数」计数器
roomLoad: Uint16Array // [roomId * slotCount + slotId] = 已占班位数
// 可放置判定：
//   roomLoad[r][t] + slotsTaken(subject, r) <= concurrentCapacity[r]
```

> **这是场地并发容量带来的关键实现差异**：教师和班级可以用位图（占用是布尔的），但场地必须用计数器（占用是整数的）。三者不能用同一套结构，实现时容易写错，需在代码注释中明确标注。
>
> 单双周场景下，计数器需按 `all / odd / even` 分三份维护：`roomLoad[all] + roomLoad[odd] ≤ cap` 且 `roomLoad[all] + roomLoad[even] ≤ cap`。

### 3.2 AC-3 弧一致性裁剪

对每个单元，依次剔除值域中：

1. 规则值为 `FORBIDDEN` 的槽（教师/班级/学科/年级/全局，逐级合并，取最严）
2. 非本学段的槽（`time_slot.stage_id` 不匹配）
3. 非教学槽（`is_teaching = 0`）
4. 被 `fixed_lesson` 占用的槽
5. 不满足教室类型要求的教室
6. 连堂块：起始节次不满足"同日相邻且不跨分段"的槽

裁剪后若某单元 $D_l = \emptyset$ → 立即判定不可行，并输出是哪条规则导致。

### 3.3 可行性判定与无解诊断

**资源总量校验**（快速粗筛）：

```
for each 教师 p:   需求课时 = Σ 其任务课时;  供给 = 可用槽数
                    若 需求 > 供给 → 报"教师 p 课时超限 X 节"
for each 班级 c:   Σ 周课时 ≤ 可用教学槽数
for each 场地 r:   Σ 指定该场地的课时 × slots_taken
                    ≤ concurrent_capacity(r) × 可用槽数
for each 学科 s(需专用场地):
                    Σ 该科周课时 ≤ Σ_{r ∈ 可用场地} concurrent_capacity(r) × 槽数
```

> **体育课的典型算例**：初中 60 个班，每班 3 节体育 = 180 节/周。
> 场地供给：田径场(4 班位) + 篮球场(3) + 风雨操场(2) = 9 班位/槽。
> 每周教学槽 5 天 × 7 节 = 35 槽（扣除不排体育的时段后约 25 槽）。
> 供给 = 9 × 25 = **225 班位** > 需求 180 ✓ 可行。
> 若按旧模型（每场地独占 1 班），供给仅 3 × 25 = 75 < 180，**必然误报无解**。这正是必须引入并发容量的原因。

**逐槽二分图匹配**（精确）：对每个时间槽，构建「待排任务 → 可用资源」二分图，用 Hopcroft-Karp 求最大匹配。若存在槽无法完美匹配，提取**违反霍尔条件的最小紧缩集**，输出：

```
周二第2节 · 初二年级
  需求：8 个班需排体育
  供给：体育教师 3 人、运动场地 2 处 → 最多可排 3 个班
  缺口：5 个班
  建议：
    ① 增配 2 名体育教师并增开 1 处场地
    ② 或将初二年级体育课的「周二第2节」规则值由「优选」改为「常规」，
       允许算法分散到其他时段
```

> 输出风格：**平实、可执行**，不炫技。这是防止评委录错数据后卡死的保险丝。

### 3.4 规则矛盾自检

| 检查项                 | 示例                                     |
| ---------------------- | ---------------------------------------- |
| 某任务所有槽被禁       | 教师 A 禁排周一~周五全部时段，却分配了课 |
| 连堂不可能             | 要求连堂 3 节，但每个分段最多 2 节       |
| 拼合组成员时段交集为空 | 组内两班的可用槽无交集                   |
| 每日上限与周课时矛盾   | 周 6 节但每日上限 1 且只有 5 天          |
| 专用教室不足           | 需实验室的课时数 > 实验室数 × 槽数       |

## 4. 阶段 1：构造可行解

### 4.1 排入顺序（关键）

```
1. fixed_lesson 预排锁定  →  直接落位
2. 连堂块单元            →  自由度最低，先排
3. 拼合/同时上课组        →  多班联动，约束强
4. 需专用教室的单元       →  资源稀缺
5. 主课（importance ≥ 4） →  质量影响最大
6. 其余单元
```

### 4.2 DSATUR 贪心

```ts
function dsatur(units: Unit[], ctx: Ctx): Solution {
  const unassigned = new PriorityQueue(units, cmp)
  while (!unassigned.isEmpty()) {
    // MRV + 饱和度 + 度：最受约束者优先
    const u = unassigned.popBy((u) => [-saturation(u), -domainSizeRemaining(u), -degree(u)])

    const candidates = feasibleSlots(u, ctx) // 位图求交，O(slots/32)
    if (candidates.length === 0) {
      ctx.unplaced.push(u)
      continue
    }

    // LCV：选对未来伤害最小、且软罚分最低的槽
    const best = minBy(
      candidates,
      (slot) => softPenalty(u, slot, ctx) * 1.0 + futureImpact(u, slot, ctx) * 0.6
    ) // 该槽被多少其他单元需要

    assign(u, best, ctx)
    unassigned.updateNeighbors(u) // 更新饱和度
  }
  return ctx.solution
}
```

### 4.3 min-conflicts 修复

对 `unplaced` 中的单元：随机挑一个，放入**冲突最少**的槽（允许暂时冲突），然后把被顶掉的单元重新入队。迭代上限 $50|L|$，带随机重启。

实践中 DSATUR + min-conflicts 在 240 班算例上可在 8 秒内达到**硬约束 = 0**。

## 5. 阶段 2：ALNS 主优化

```ts
function alns(sol: Solution, ctx: OptimizeContext): Solution {
  let cur = sol,
    best = clone(sol)
  const destroyOps = [randomRemove, worstRemove, shawRemove, teacherDayRemove, classDayRemove]
  const repairOps = [greedyInsert, regret2Insert, regret3Insert, hungarianRematch]
  const wD = destroyOps.map(() => 1),
    wR = repairOps.map(() => 1)

  while (!timeUp(ctx) && !ctx.signal.cancelled) {
    const di = rouletteSelect(wD),
      ri = rouletteSelect(wR)
    const k = randomInt(0.05 * L, 0.2 * L) // 破坏规模：5%~20%

    const removed = destroyOps[di](cur, k)
    const cand = repairOps[ri](cur, removed, ctx)

    let psi = 0
    if (cost(cand) < cost(best)) {
      best = clone(cand)
      cur = cand
      psi = 33
    } else if (cost(cand) < cost(cur)) {
      cur = cand
      psi = 9
    } else if (accept(cand, cur, ctx)) {
      cur = cand
      psi = 3
    } // 退火式接受

    wD[di] = 0.8 * wD[di] + 0.2 * psi // 自适应权重
    wR[ri] = 0.8 * wR[ri] + 0.2 * psi
    ctx.onProgress({ phase: 'optimize', best: cost(best) })
  }
  return best
}
```

**破坏算子**

| 算子               | 策略                                                  |
| ------------------ | ----------------------------------------------------- |
| `randomRemove`     | 随机拆 k 节                                           |
| `worstRemove`      | 拆罚分贡献最高的 k 节                                 |
| `shawRemove`       | 拆与随机种子课"相关"的一簇（同教师/同班/同日/同学科） |
| `teacherDayRemove` | 拆某教师某日全部课，整日重排（**对 S6/S7 最有效**）   |
| `classDayRemove`   | 拆某班某日全部课（**对 S1/S10 最有效**）              |

**修复算子**

| 算子               | 策略                                                 |
| ------------------ | ---------------------------------------------------- |
| `greedyInsert`     | 按最小增量罚分逐个插回                               |
| `regret2/3Insert`  | 优先插入"最佳与次佳位置差距大"的单元，避免好位置被抢 |
| `hungarianRematch` | 被拆单元 × 空槽构建代价矩阵，匈牙利算法求最优指派    |

## 6. 阶段 3：LAHC 精修 + Kempe 链

```ts
function lahc(sol: Solution, ctx: OptimizeContext, L = 5000): Solution {
  let cur = sol,
    best = clone(sol)
  const hist = new Float64Array(L).fill(cost(cur))
  for (let i = 0; !timeUp(ctx); i++) {
    const mv = pickMove(ctx.moves) // swap / kempe / blockMove / move
    const d = mv.deltaCost(cur, ctx.scorer) // ★ 增量评分
    const v = i % L
    if (cost(cur) + d <= hist[v] || d <= 0) {
      mv.apply(cur)
      if (cost(cur) < cost(best)) best = clone(cur)
    }
    hist[v] = cost(cur)
  }
  return best
}
```

### Kempe 链交换

```
KempeChain(sol, lesson v, slot t1, slot t2):
  # 在 t1 ∪ t2 两个时段的课程构成的子图上，取含 v 的连通分量
  comp ← BFS(v, 邻接 = 共享班级/教师/教室)
  # 整块对调
  for u in comp: u.slot ← (u.slot == t1 ? t2 : t1)
```

**性质**：由图着色的 Kempe 定理，交换后**必然仍无冲突**。这是唯一能一次性重构十几节课布局、且保证可行性的大步长算子，是逃离局部最优的关键。

### 增量评分（性能命门）

```ts
interface Scorer {
  full(sol: Solution): number
  /** 只重算受影响维度：涉及的班级×日、教师×日、学科×班 */
  delta(sol: Solution, changed: Unit[]): number
}
```

维护增量缓存：

```ts
classDayCount[classId][day][subjectId]   // S1, S10
teacherDaySlots[teacherId][day]: bitmap  // S6, S7, S12
subjectDayMask[classId][subjectId]       // S2
```

每次 Move 只更新受影响条目，评分从 $O(N)$ 降到 $O(k)$，$k \le 20$。**实测迭代吞吐从 3k/s 提升到 400k/s。**

## 7. 阶段 4：抛光（Polish）—— 本项目独有

> **动机**：评委用眼睛而不是用评分函数判断。评分函数的全局最优，可能仍残留几处"一眼扎眼"的安排。抛光阶段用确定性规则专门清除它们。

```
POLISH(sol):
  repeat until 无改进 or 达到 5% 时间预算:

    # P1 消除教师空隙课（最扎眼）
    for 每位教师 p, 每一天 d:
      gaps ← 首末节之间的空档
      for 每个 gap: 尝试将该教师当日某节课平移填补（Kempe/swap），
                     仅当不增加总罚分时执行

    # P2 消除同班同日三连同科
    for 每班 c, 每日 d, 每科 s: 若 ≥3 节，强制移走超出部分

    # P3 消除下午连排三节主课
    for 每班 c, 每日 d: 若下午连续 3 节 importance≥4，与该班当日上午副课对调

    # P4 补齐学科周内空白
    for 每班 c, 每科 s: 若某科 5 天内集中于 2 天，尝试摊开

    # P5 教师首末节优化
    尽量让教师的课集中在连续时段，减少"早来晚走"

    # P6 连堂对齐
    确保所有连堂块相邻且不跨午休
```

每条规则都是**"仅当总罚分不升高时才执行"**的安全变换，不会破坏前序优化成果。

## 8. 增量重排（动态调整）

触发：新增/删除班级、教师调岗、教室检修、手工改动后要求"重排剩余部分"。

```
1. 计算受影响单元集合 A：
   - 直接受影响：涉及变更实体的课时
   - 传播一层：与 A 共享班级/教师/教室时段的课时
2. 冻结 L \ A（标记 is_locked 语义）
3. 仅对 A 跑：构造 → ALNS（短预算）→ LAHC → Polish
4. 启用 S11「与基线差异」软约束，权重 50，最大化保持稳定
5. 输出差异报告：新增 X 节、移动 Y 节、未变 Z 节
```

## 1. 架构总览

单机桌面应用，**三进程模型**：

```
┌──────────────────────────────────────────────────────────────┐
│ Electron Main Process（Node.js）                              │
│  · 窗口与生命周期  · 菜单/托盘  · 文件对话框                   │
│  · SQLite 数据访问层（better-sqlite3，同步 API）              │
│  · IPC 路由（typed channel）                                  │
│  · 导出服务（Excel / PDF / PNG）                              │
└───────────┬──────────────────────────────┬───────────────────┘
            │ IPC (contextBridge)          │ worker_threads
            ▼                              ▼
┌───────────────────────────┐  ┌──────────────────────────────┐
│ Renderer（React + TS）     │  │ Solver Worker（纯 TS，无 IO） │
│  · UI 全部页面             │  │  · 预处理 / 构造 / 优化       │
│  · Zustand 状态            │  │  · 增量评分                   │
│  · 课表网格与拖拽          │  │  · 进度事件回传、可取消       │
│  · 客户端冲突即时校验      │  │  · 多实例并行（多起点）       │
└───────────────────────────┘  └──────────────────────────────┘
```

### 1.1 为什么这样切

| 决策 | 理由 |
|---|---|
| 引擎放 **Worker 线程**而非主进程 | 排课是 CPU 密集型，放主进程会冻结窗口；Worker 可并行多起点，可随时 terminate 实现"取消" |
| 引擎**纯函数、零 IO** | 输入一个 `SolverInput` 快照，输出 `SolverResult`。便于单元测试、便于跑离线基准实验、便于未来换语言 |
| SQLite 访问只在**主进程** | 避免多线程写冲突；`better-sqlite3` 同步 API 在主进程用最简单 |
| 渲染进程**不直接碰数据库** | `contextIsolation: true`，通过类型化 IPC 通信，安全且可测 |
| 渲染进程内置**轻量冲突校验器** | 拖拽时必须 <100ms 响应，不能走 IPC 往返。共享同一份 `constraints` 纯逻辑模块 |

## 2. 技术栈

### 2.1 选型表

| 层 | 技术 | 版本 | 理由 |

| 数据请求 | TanStack Query | 5.x | IPC 调用的缓存与失效管理 |
| 表格 | TanStack Table | 8.x | 教学任务矩阵、基础数据列表 |
| 拖拽 | **dnd-kit** | 6.x | 比 react-dnd 更现代，支持碰撞检测自定义与无障碍 |

| 图表 | Recharts | 2.x | 体检报告的负荷分布图 |
| 虚拟滚动 | TanStack Virtual | 3.x | 全校总表 240 列的性能保证 |
| 数据库 | **better-sqlite3** | 11.x | 同步 API、性能最好、无需 async 污染 |
| 迁移 | 自研轻量 migration runner | - | 按版本号顺序执行 SQL 文件 |
| Excel | ExcelJS | 4.x | 纯 JS，样式能力强于 SheetJS 社区版 |
| PDF | **Electron 内置 `printToPDF`** | - | 用 HTML+CSS 排版打印页，质量最好且零额外依赖 |
| 图片 | `webContents.capturePage` / html-to-image | - | PNG 导出 |
| 打包 | electron-builder | 24.x | NSIS 安装包 + portable 免安装 |
| 测试 | Vitest + Playwright | - | 引擎单测 + E2E |

### 2.2 明确不引入

OR-Tools / 任何原生编译的求解器（打包地狱）、ORM（Prisma 在 Electron 打包麻烦，直接写 SQL + 薄 Repository 层）、状态机库、i18n（本期仅中文）。

## 4. 数据流

### 4.1 排课流程

```
用户点「开始排课」
   │
   ▼
Renderer → IPC: schedule:start { semesterId, styleProfile, scope }
   │
   ▼
Main: SolverService
   ├─ 从 SQLite 读全量数据 → 组装 SolverInput（纯数据快照）
   ├─ new Worker(solver/worker.ts)  × N（多起点并行）
   └─ 监听 worker message
        ├─ { type:'progress', phase, percent, bestScore }  → IPC push → Renderer 进度条
        ├─ { type:'infeasible', diagnosis }                → 无解诊断弹窗
        └─ { type:'done', solution, report }               → 落库 + 生成版本快照 → 通知 Renderer
```

**取消**：Renderer 发 `schedule:cancel` → Main 调 `worker.terminate()`，并保留已产生的最优解供用户选择采用。

### 4.2 拖拽换课流程（要求 <100ms）

```
onDragStart  → 渲染端用 shared/constraints 计算「所有合法落点」，高亮可放置格
onDragOver   → 本地即时判定冲突等级（绿/黄/红），无 IPC
onDrop       → 本地先行更新 UI（乐观更新）+ 推入撤销栈
             → 异步 IPC 落库；失败则回滚并提示
```

## 5. IPC 接口设计

统一约定：通道名 `域:动作`，全部类型化。

```ts
// src/shared/types/ipc.ts
export interface IpcApi {
  // 基础数据
  'grade:list':   (semesterId: number) => Grade[];
  'grade:upsert': (payload: GradeInput) => Grade;
  'class:batchCreate': (p: { gradeId: number; count: number; namePattern: string }) => Klass[];
  // ... 各实体同构

  // 教学任务
  'matrix:get':   (semesterId: number) => TeachingMatrix;
  'matrix:set':   (cells: MatrixCell[]) => void;

  // 规则
  'rule:getTimeGrid': (scope: RuleScope) => RuleValue[][];
  'rule:setTimeGrid': (scope: RuleScope, grid: RuleValue[][]) => void;

  // 排课
  'schedule:selfCheck': (semesterId: number) => SelfCheckResult;
  'schedule:start':     (p: StartParams) => { taskId: string };
  'schedule:cancel':    (taskId: string) => void;
  'schedule:adjust':    (p: AdjustParams) => AdjustResult;
  'schedule:suggestSwap': (lessonId: number) => SwapSuggestion[];

  // 课表
  'timetable:byClass':   (classId: number) => TimetableView;
  'timetable:byTeacher': (teacherId: number) => TimetableView;
  'timetable:overview':  (semesterId: number) => OverviewView;

  // 报告与版本
  'report:health':   (versionId: number) => HealthReport;
  'version:list' | 'version:rollback' | 'version:diff': ...;

  // 导出
  'export:excel' | 'export:pdf' | 'export:png': (p: ExportParams) => { filePath: string };

  // 系统
  'seed:load':  (preset: 'primary' | 'junior' | 'senior') => void;
  'seed:clear': () => void;
}
```

事件推送（Main → Renderer）：`schedule:progress`、`schedule:done`、`schedule:failed`。

## 7. 性能设计

| 措施 | 说明 |
|---|---|
| **增量评分** | Move 只重算受影响课时的罚分，$O(k)$ 而非 $O(N)$，迭代吞吐提升两个数量级 |
| **位集冲突检测** | 教师/班级/教室的占用用 `Uint32Array` 位图，冲突判定 O(1) |
| **分治** | 按年级切子问题并行求解，再做共享资源（教师/专用教室）协调 |
| **多起点并行** | `worker_threads` 开 `min(CPU核数, 8)` 个 Worker，不同随机种子，取最优 |
| **UI 虚拟化** | 全校总表 240 列用 TanStack Virtual |
| **SQLite 调优** | `journal_mode=WAL`、`synchronous=NORMAL`、批量写用事务包裹 |
| **乐观更新** | 拖拽先改 UI 后落库 |

## 8. 错误与稳定性

| 场景 | 处理 |
|---|---|
| Worker 崩溃 | 主进程捕获 `exit` 事件，回退到单线程兜底求解，并提示 |
| 排课超时 | 到达时间预算即返回当前最优解，标注"已达时间上限" |
| 无解 | 不抛异常，返回 `infeasible` + 诊断报告 |
| 数据库损坏 | 启动时 `PRAGMA integrity_check`，损坏则引导用户从备份恢复 |
| 未捕获异常 | 全局兜底，写日志到用户目录，界面显示友好错误页而非白屏 |

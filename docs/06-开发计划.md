## 3. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| `better-sqlite3` 原生模块打包失败 | 致命 | **M0 就验证打包链路**，不要留到最后；备选 `node:sqlite`（Node 22+）或 sql.js |
| 课表质量不达标，评委抽查出问题 | 高 | M5 建立回归指标断言，每次改动跑基准；Polish 阶段专治"人眼可见瑕疵" |
| 240 班性能不达标 | 中 | 分治 + 多起点并行 + 位图 + 增量评分；实在不行降级宣传规模 |
| 拖拽交互卡顿 | 中 | 约束判定纯本地 + 乐观更新；课表用 CSS Grid 而非绝对定位 |
| UI 精致度不足 | 高 | M4 单独作为一个里程碑，不与功能混做；严格执行设计 token |
| 范围蔓延 | 高 | M9 全部是选做；M1~M8 完成即可交付 |

## 4. 工程约定

**分支**：全部工作在当前 Arena 会话自动分配的 `arena/*-courseschedulingsystem` 分支上；该分支名每次开新会话都会变（是上一个会话分支的延续），**不要在指令或文档里写死具体分支名**，也不要尝试切换到别的分支。

**提交信息**：
```
feat(solver): 实现 Kempe 链交换算子
fix(timetable): 修复连堂块跨午休的渲染错位
docs: 更新算法设计文档
chore(build): 配置 electron-builder portable 目标
```

**代码约定**：
- 引擎目录 `src/solver/**` **禁止** import Electron / Node 内置模块（除 `worker_threads` 入口文件），保证可单测、可离线基准
- 所有 IPC 通道必须在 `shared/types/ipc.ts` 声明类型
- 冲突判定逻辑只有一份，位于 `shared/constraints`
- 数据库变更一律新增 migration 文件，不修改历史文件

**测试**：
- 引擎：Vitest 单测覆盖 11 条硬约束 + 13 条软约束评分 + 各 Move 的 apply/undo 幂等性
- 基准：`npm run bench` 输出五组算例指标表
- E2E：Playwright 覆盖「载入示例 → 排课 → 拖拽 → 导出」主流程

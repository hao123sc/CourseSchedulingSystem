## 零、先讲清楚问题本质（评审答辩开场用）

排课问题（University/School Timetabling Problem, **UTP/STP**）是**约束满足与组合优化的交叉问题**，在计算复杂性上等价于**图着色问题**，已被证明是 **NP-完全**的。

> **图着色等价性**（这是答辩时最漂亮的一句话）：
> 把每一节"待排课程"看作图的一个**顶点**；若两节课共享同一教师、同一班级或同一教室，则在它们之间连一条**边**；每个"时间槽"是一种**颜色**。
> 于是「排出无冲突课表」⟺「用不超过 T 种颜色给这张冲突图着色」。
> 这一转化使得图着色领域几十年的成熟算法（DSATUR、Kempe 链、Tabu-Col）可以直接迁移过来。

**规模估算（本项目设计容量）**：240 班 × 平均 35 课时/周 = **8400 个变量**，每个变量的值域为 {5 天 × 9 节} × 可用教室 ≈ 45~200 个取值。朴素搜索空间量级 $10^{15000}$ 以上，**穷举不可能**，必须用启发式。

## 二、重点算法详解（答辩讲稿级）

### A2 二分图匹配 + 霍尔定理 —— 无解诊断的数学依据

**为什么值钱**：几乎所有排课系统在无解时只会转圈或报"排课失败"。本项目能说出**"为什么无解、缺什么、缺多少"**。

对任一时间槽 $t$，构造二分图：左部为该槽需要上课的教学任务，右部为可用教师/教室资源。由 **Hall 定理**，完美匹配存在的充要条件是：任意任务子集 $S$，其可用资源邻域满足 $|N(S)| \ge |S|$。

违反 Hall 条件的**最小紧缩集**（deficiency set）就是瓶颈所在，可直接翻译成人话：

> "周二上午第 2 节，初二年级有 8 个班需要体育课，但只有 3 名体育教师和 2 个场地 —— 最多满足 3 个班，缺口 5。建议：① 增加 2 名体育教师；② 或将其中 5 个班的体育课移出该时段。"

这一段是**演示环节的高光时刻**。

### A3 图着色贪心 DSATUR —— 构造阶段主力

DSATUR（Degree of Saturation）每步选择**饱和度最高**（已被邻居占用的颜色数最多）的顶点着色，平局时选度数最大者。

```
DSATUR(冲突图 G, 颜色集 T):
  未着色集 U ← V(G)
  while U ≠ ∅:
    v ← argmax_{u∈U} ( 饱和度(u), 度(u) )        # 最受约束者优先
    C ← T \ {邻居已用颜色} \ {规则值=FORBIDDEN 的时段}
    if C = ∅: 记录 v 为"未安置"，进入修复阶段
    else:     给 v 着色 argmin_{c∈C} 软约束惩罚(v,c)   # LCV：挑罚分最小的时段
    U ← U \ {v}
```

- **复杂度**：$O(V^2 + VT)$，8400 个变量在毫秒~秒级完成
- **优点**：比随机贪心质量高一大截，且"最受约束者优先"这一直觉极易向评委解释
- **与 CSP 的关系**：DSATUR 本质就是带 MRV + 度启发式的贪心，可无缝退化/升级为 A4 的回溯搜索

### A8 迟到接受爬山 LAHC —— 性价比之王，强烈建议实现

**只有一个参数**（历史列表长度 $L$），却常常打平甚至优于精心调参的模拟退火。Burke & Bykov 提出，正是在**考试与课表编排**领域验证的。

```
LAHC(初始解 s, 列表长 L):
  f ← cost(s);  history[0..L-1] ← f;  best ← s
  for i = 0, 1, 2, ...:
    s' ← 随机邻域动作(s)                    # 见第三节算子库
    v  ← i mod L
    if cost(s') ≤ history[v] or cost(s') ≤ cost(s):
        s ← s'                              # 接受
    history[v] ← cost(s)
    if cost(s) < cost(best): best ← s
  return best
```

**为什么写进评审表有优势**：

- 相对冷门，评委大概率没见过 → 显示你做过真正的文献调研，而不是百度"排课算法"
- 无需设计冷却曲线，**不存在"参数调不好"这一被追问的软肋**
- 代码不到 30 行，实现成本近乎为零

### A9 自适应大邻域搜索 ALNS —— 建议作为默认主引擎

思路：每轮**破坏**（destroy）当前解的一部分，再**修复**（repair）。关键在于**算子权重自适应**——表现好的算子被选中的概率自动上升（轮盘赌 + 权重衰减）。

| 破坏算子         | 说明                                           |
| ---------------- | ---------------------------------------------- |
| 随机移除         | 随机拆掉 k 节课                                |
| 最差移除         | 拆掉罚分最高的 k 节课                          |
| 关联移除（Shaw） | 拆掉与某节课"相关"（同教师/同班/同天）的一簇课 |
| 教师整日移除     | 拆掉某教师某天全部课程，重排其日程             |
| 班级整日移除     | 拆掉某班某天全部课程                           |

| 修复算子             | 说明                                   |
| -------------------- | -------------------------------------- |
| 贪心插入             | 按罚分最小位置逐个插回                 |
| 后悔值插入(Regret-k) | 优先插入"若不现在插、代价会暴涨"的课   |
| 匈牙利重匹配         | 对被拆课程与空槽做最优指派（调用 A12） |

**权重更新**：$w_i \leftarrow \lambda w_i + (1-\lambda)\,\psi$，其中 $\psi$ 依据本轮该算子是否产生「新全局最优 / 改进解 / 被接受的劣解」分档给分。

**评审价值**：这是物流调度、车辆路径等工业场景的主流方法，把它迁移到排课上，**"跨领域方法迁移"本身就是创新点的合法表述**。且 UI 上可实时展示各算子权重的动态变化柱状图，视觉效果极佳。

### A11 Kempe 链交换 —— 跳出局部最优的杀手锏

普通的"两节课互换时间"往往因为连锁冲突而不可行，导致搜索卡死。**Kempe 链**解决了这个问题：

给定两个时段 $t_1, t_2$ 和一节课 $v$，在由 $t_1 \cup t_2$ 中课程构成的子图上，取包含 $v$ 的**连通分量**，将该分量内所有课程的时段**整体对调**（$t_1 \leftrightarrow t_2$）。

**关键性质：Kempe 链交换后必然仍然无冲突**（这是图着色的经典定理）。所以它是一个**保持可行性的大步长移动**，能一次性重构十几节课的布局，是逃离局部最优的最强算子。

> 答辩点：普通交换是"一步一挪"，Kempe 链是"整块板块漂移"，而且数学上保证不会引入新冲突。

### A13 超启发式 Hyper-heuristic —— 若要冲更高奖项

不直接搜索解空间，而是**搜索"该用哪个低层启发式"的空间**。上层用强化学习式的选择策略（如 $\epsilon$-greedy / UCB 多臂老虎机），根据各低层算子近期收益动态调度 A6/A7/A8/A11 等。

这可以让你在答辩时说：**"系统不是用某一种算法排课，而是在排课过程中自主学习该用哪种算法。"** —— 这句话的分量远超"我用了遗传算法"。

实现上，ALNS 的自适应权重机制其实已经是一种简化超启发式，**升级成本很低**，建议作为 A9 的进阶形态。

### A14 多目标 / 帕累托前沿 —— 把"取舍"可视化

排课的本质矛盾是**多方利益冲突**：

| 目标               | 度量                                               |
| ------------------ | -------------------------------------------------- |
| $f_1$ 学生课表质量 | 主课上午占比、学科周内分散度、单日难度均衡         |
| $f_2$ 教师满意度   | 日课时方差、空隙课（"垃圾时间"）数、偏好时段命中率 |
| $f_3$ 资源利用率   | 专用教室空置率、场地冲突数                         |
| $f_4$ 稳定性       | 与上一版课表的差异度（动态调整时越小越好）         |

用 NSGA-II 求**帕累托前沿**，UI 上画一条前沿曲线，让用户**拖动滑块在"教师舒服"和"学生高效"之间实时选择方案**。

> 这是把技术转化为**产品洞察**的一步：排课没有唯一最优解，只有取舍。能讲出这一点的参赛者极少。

### A15 CP-SAT / ILP —— 作为「最优性基线」而非产品组件

**不打包进软件**（OR-Tools 体积大、跨平台打包麻烦），但在**离线实验**中用它求小规模算例（如 1 个年级 20 班）的最优解或下界，然后在评审材料里写：

> "在 20 班算例上，CP-SAT 求得最优软约束罚分为 128（耗时 47 分钟）；本系统 ALNS 在 6.2 秒内求得 134，**达到最优解的 95.5%，速度提升 450 倍**。"

**这张表格比任何形容词都有说服力**，是评审材料中分量最重的一段。

## 三、共享邻域算子库（各优化算法通用）

| 算子                  | 描述                        | 保持可行性 |
| --------------------- | --------------------------- | ---------- |
| Move                  | 将一节课移到空闲槽          | 需检查     |
| Swap                  | 两节课互换时段              | 需检查     |
| **Kempe Chain**       | 连通分量整体换色            | **是**     |
| Block Move            | 连堂课整体平移              | 需检查     |
| Teacher-Day Reshuffle | 某教师某日课程全排列重排    | 需检查     |
| Hungarian Rematch     | 一组课与一组空槽做最优指派  | 是         |
| Ruin & Recreate       | 破坏一簇后重建（ALNS 核心） | 是         |

统一接口设计：

```ts
interface Move {
  readonly kind: MoveKind
  apply(sol: Solution): void
  undo(sol: Solution): void
  /** 增量评分：只重算受影响部分，O(受影响课时数) 而非 O(全表) */
  deltaCost(sol: Solution, scorer: Scorer): number
}
```

> **工程要点**：增量评分（delta evaluation）是性能命门。全量评分 $O(N)$，增量评分 $O(1)\sim O(k)$，对 10 万次迭代而言是**百倍级**的差距。这一点也要写进文档，体现工程深度。

## 四、评分函数（所有算法共用的目标函数）

$$
\text{Cost}(S) = \underbrace{M \cdot \sum_{h \in H} v_h(S)}_{\text{硬约束，}M=10^6} + \underbrace{\sum_{s \in \text{Soft}} w_s \cdot v_s(S)}_{\text{软约束}}

## 五、最终推荐配置

```
┌─ 阶段0 预处理 ──────────────────────────────┐
│ A1 AC-3 约束传播  →  值域裁剪                │
│ A2 二分图匹配可行性判定  →  无解诊断报告      │
└──────────────────────────────────────────────┘
                    ↓
┌─ 阶段1 构造 ────────────────────────────────┐
│ A3 DSATUR 图着色贪心（MRV + 度 + LCV）       │
│ 失败槽位 → A5 min-conflicts 修复             │
│ A17 并行多起点：8 线程各跑一个随机种子，取优  │
└──────────────────────────────────────────────┘
                    ↓
┌─ 阶段2 优化（可插拔，UI 可切换/对比）────────┐
│ 默认：A9 ALNS（含 A11 Kempe、A12 匈牙利算子）│
│ 备选：A6 SA / A7 TS / A8 LAHC / A10 GA       │
│ 进阶：A13 超启发式自动调度上述算子            │
│ 收尾：A8 LAHC 精修 2 万次迭代                 │
└──────────────────────────────────────────────┘
                    ↓
┌─ 阶段3 交付 ────────────────────────────────┐
│ 课表体检报告 + A14 帕累托方案组（可选）       │
│ 人工微调 → A5 增量修复                       │
└──────────────────────────────────────────────┘
```

**大规模（240 班）性能策略**：

1. **分治**：按学段/年级切分为弱耦合子问题（跨年级共享的只有教师与专用教室），先独立求解，再用"共享资源冲突消解"阶段做全局协调
2. **并行**：Node.js `worker_threads` 多线程跑多起点 / 多算法
3. **增量**：动态调整时冻结未受影响区域，只对受影响子图重排（配合 S11 稳定性权重）

## 六、写进评审表的话术（可直接摘用）

> 本系统构建了**可插拔的多算法排课求解框架**。通过将排课问题形式化为**图着色与约束满足的复合模型**，系统实现了 3 类共 9 种求解算法：预处理层采用 AC-3 弧一致性与二分图匹配理论，实现了**基于霍尔定理的无解成因诊断**，可精确定位资源瓶颈并给出量化改进建议；构造层采用 DSATUR 饱和度启发式图着色算法；优化层实现了模拟退火、禁忌搜索、迟到接受爬山与自适应大邻域搜索四种元启发式算法，并共享包含 **Kempe 链交换**这一保可行性大步长算子在内的统一邻域算子库，配合**增量评分机制**实现了百倍级的迭代吞吐提升。
>
> 系统内置**算法对比实验台**，支持多算法在同一算例上并行竞速并实时绘制收敛曲线。以 OR-Tools CP-SAT 求得的精确最优解为基线的对标实验表明，本系统自适应大邻域搜索算法可在 **X 秒内达到最优解 95% 以上的解质量，求解速度提升两个数量级**，可支撑 12 个年级、240 个教学班规模的中小学全学段排课需求。
